# humanize-check — 人性化 · 易读独立复检门禁 Skill

`humanize-check` 是定稿前的**最后一道门禁**:拿一份已经做完的胶片 / 文档 / 网页 / 月刊周报,用一个不带作者语境的视角重读一遍,把「读起来别扭、不像人话、只说一半、模棱两可」的地方挑出来并改掉。

为什么必须独立跑:作者对自己写的句子会「读顺」——那些别扭的措辞在写的时候是有语境的,回头再看仍然读得通。只有换一个视角,才能发现「这句话别人看不懂」。

## 通用收尾门禁:一处维护,处处受益

本 skill 不绑定任何一种产物形态,**任何「最终产物是给人读的文字」的 skill 都可以在收尾时调用它**:

| 调用方 | 产物 | 在哪一步调 |
|---|---|---|
| `pptx-pro` | 决策胶片 / 汇报页 | 渲染目检通过后、存版本前 |
| 月刊 / 周报 / 简报类 skill | 中文 digest、动态汇总 | 拼完全文、发出前 |
| 博客 / 文稿类 skill | 公众号文章、技术博客 | 定稿前 |
| 设计文档 / 分析报告类 skill | Markdown + docx、评估报告 | 交付前 |

这样一来,「已纠正表达对照表」、结论先行、术语一致、标点跟随文种这些规则**只需要维护一份**,不必在每个产物型 skill 里各抄一遍;改一次,所有调用方同时受益。

## 主要能力

- **黑话与生硬措辞替换**:内部黑话、虚指大词、口语化疑问式标题、「好消息 / 坏消息」框架词、动宾不搭配、生造的「XX 税」类套壳比喻,逐类给 before→after;另附一张 **38 条的已纠正表达对照表**(直译腔、比喻空转、江湖气、学术腔、残缺压缩短语等),遇到即改,并从中抽出 7 条通用规则单独记住。
- **完整性与结论性**:关键点有没有「只说一半」;结论有没有明确观点(推荐哪个 + 为何不选其他)。
- **结论先行**:每节开头两句必须能让读者复述出本节结论,而不是目录式导语。
- **一致性扫描**:同一概念的不同写法、大小写、简写 vs 全写、产品名混用、前后口径矛盾。
- **中文排版**:标点跟随文种(可调用同仓 `pptx-pro` 的 `punct-normalize.py` 批量修);HTML 场景额外查四个「只在浏览器里才看得见」的中文排版坑。
- **默认就地改**:能自己定夺的直接改并重渲染核对;会变更事实数字 / 业务取舍的只报不改。
- **两阶段流程 + 自我进化**:机械阶段(按清单与对照表逐条过、能脚本化的先脚本化)→ 独立挑刺阶段(另起一个不共享作者上下文的 agent 出分级报告)→ **回写迭代**:本轮确认的新坏表达进对照表、新类型问题进清单,下一轮的机械阶段就能拦住这一轮的漏网。

## 依赖

| 依赖 | 用途 | 是否必需 |
|---|---|---|
| Python + markitdown | 提取 pptx 正文 | 检查 pptx 时必需 |
| LibreOffice(`soffice`)+ poppler(`pdftoppm`) | 渲染出图看观感 | 检查 pptx 时必需 |
| 无头浏览器(`--headless --screenshot`) | 网页渲染核对 | 检查 HTML 时必需 |
| 同仓 `pptx-pro` skill | 复用 `references/punct-normalize.py` 做标点归一 | 可选,手工改也行 |

## 快速使用

```bash
# 对一份胶片做复检(通常由 pptx-pro 收尾时起独立 subagent 调用)
humanize-check /path/to/deck.pptx

# 也可直接对 md / HTML 用
humanize-check /path/to/report.md
```

## 输出格式

结尾给一个明确结论,三选一:

- **通过** —— 没有需要改的点;
- **已改 N 处** —— 逐条列 `[类别] 位置 —— 现状 → 已改成`;
- **待人定夺 M 条** —— 逐条列 `[类别] 位置 —— 现状 → 建议`,交需求方拍板。

## 硬性红线

**凡是经过核验的报告,一个数字都不许改。** 改完自查:把改动前后的全部数值抽成多重集比对,差集应当为空(新增解释性文字带进来的数字除外)。这是最容易犯、后果最重的错。
