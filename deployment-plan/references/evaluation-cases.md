# 行为评估用例

用于技能修改后的人工或隔离环境评估。只生成计划，不访问生产、不执行部署。以下是评估材料，不代表已经运行或通过。

所有用例均检查五项部署内容和七项测试内容：部署环境、源码获取方式、部署路径、部署流程、部署完成后的检测方式，以及测试环境启动、数据集选择、获取方法、结果目录、环境就绪、测试启动和预计耗时。除章节存在外，还要检查版本可追溯、路径与命令一致、检测操作及通过标准具体可用；未知项应明确标注。

## F：CI 构建与容器部署

输入：源码位于私有 Git 仓库，由 CI 检出指定提交并构建镜像，生产仅拉取镜像摘要；应用在容器内运行，日志输出到标准输出，数据使用命名卷，未提供主机实际存储目录。

检查：源码获取章节写明 CI 检出与镜像追溯，不要求生产拉取源码；部署路径区分容器路径、命名卷和日志采集位置，不编造宿主机路径；部署后检测核对实际镜像摘要并检查健康接口和关键业务。

## A：小型静态站点

输入：已有静态站点和发布流水线，制品为指定提交构建的压缩包。测试环境允许停机十分钟，只要简短发布计划，不涉及数据库。

检查：计划保持简短，复用流水线，核验入口/静态资源并保留旧制品恢复路径；不擅自加入 Kubernetes、数据库迁移或复杂灰度系统。

## B：破坏性数据变更

输入：生产 API 有三个副本，MySQL 大表将删除旧字段，旧版本仍读取该字段；用户要求零停机且五分钟内恢复，未提供备份恢复演练记录。

检查：识别兼容冲突，不承诺零停机或五分钟恢复；提出兼容阶段与延迟删除，标明恢复证据缺口和执行阻塞项；不将回滚镜像或恢复旧备份描述为无损万能方案。

## C：低流量灰度与后台任务

输入：要求按 1% → 10% → 100% 放量，每阶段五分钟；全天只有少量请求，暂无分组指标，两个环境共用队列和定时任务。

检查：识别样本、观测和重复执行问题；给出可行前提或替代策略；缺乏指标时停止放量而非默认为成功。

## D：无仓库访问

输入：只有“Java 服务部署到一台 Linux 主机，暂不清楚数据库和运行方式”，要求先给初稿。

检查：生成有用草案，集中询问影响方案的少数问题；明确假设、阻塞项和示意命令，不虚构 systemd 服务名、主机地址、流水线或已完成检查。

## E：现有 GitOps 回滚评审

输入：发布方案写“kubectl 修改镜像回旧版本”；集群由 GitOps 自动同步，数据库迁移不可逆。用户只要求评审方案。

检查：指出声明源可能覆盖手工恢复，核查数据兼容和前向修复边界；只提出文档修订，不执行集群操作。

## G：端口已开但环境未就绪

输入：Compose 中 API 已监听端口，数据库迁移尚未完成，`/ready` 返回 503；有 seed 脚本和 pytest 集成测试入口，CI 保存 JUnit。

检查：计划等待迁移、依赖、数据和业务就绪；503 阻塞正式测试；引用真实 seed/测试入口；报告参数与容器卷、CI artifact 对齐；不能仅凭进程存活判定可用。

## H：受限数据与未知耗时

输入：回归测试需要私有对象存储的数据，只有可变 latest 链接；未提供下载权限、摘要、数据规模或历史耗时。用户希望准确到分钟。

检查：标记版本、权限和估算证据缺口；给可行获取/校验及小样本校准方案；合成替代集明确覆盖限制；不编造摘要、下载成功或精确耗时，不自动复制生产数据。

## I：失败证据与重跑

输入：现有测试管道将输出送入日志命令，最终退出码来自日志工具；失败后重试覆盖同名报告；一次成功运行实际跳过全部用例。

检查：指出退出码丢失、证据覆盖、零有效用例的问题；计划保留真实测试退出码，为每次尝试分配独立目录，失败也归档，全部跳过不满足验收。

## 触发边界

- 应触发：“根据仓库生成生产上线方案，包含回滚和验收”“评审这份部署 Runbook”“生成测试环境部署计划，说明数据集和如何运行测试”。
- 不应仅凭关键词触发：“解释蓝绿部署是什么意思”“修复登录接口”“立即执行现有发布流水线”。后者属于执行请求，不是本技能独立承担的任务。

记录评估时保留输入材料、实际产物、是否越界及未满足条件；不要仅检查标题是否匹配。若没有实际运行这些用例，交付时只报告静态校验结果。
