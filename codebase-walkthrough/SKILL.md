# 源码带读（Codebase Walkthrough）

对陌生仓库做系统性深度讲解，帮用户建立可迁移的心智模型，而不是罗列文件。

## 输出结构（固定五段）
1. **一句话定位**：这个项目是什么、解决什么问题、属于哪类架构范式。
2. **整体骨架**：目录/模块分层鸟瞰（配 architecture-diagram 的分层图可选），先给全局再进细节。
3. **一次请求的生命周期主线**：挑一条最具代表性的真实链路，从入口→处理→出口逐步走，每步标 `文件:行号`。这是理解的脊柱。
4. **设计哲学小结**：为什么这么分层、关键取舍、值得注意的模式（如事件驱动、双层调度、上下文隔离）。
5. **推荐阅读顺序 + 深挖方向**：按依赖/由浅入深给出该读哪几个文件的顺序，并列出可选的下一步专题。

## 工作流
1. **先探后讲**：用文件搜索/读取工具（必要时派探索型子智能体）扫目录、找入口、定位关键函数，建立真实锚点。**绝不凭记忆标 `文件:行号`**。
2. **抓主线优先**：从 CLI/HTTP/事件入口顺藤摸瓜，锁定一条端到端真实路径，别被边角文件带偏。
3. **锚点可跳转**：每个论断配 `文件:行号`，让用户能点开验证。
4. **语言**：用用户交流的语言（默认中文）。
5. 需要可视化骨架时，接 `architecture-diagram` skill。

## DSH 适配
- 「先探后讲」的探索用 DSH 内置的文件读取 / grep / glob / 子智能体（官方子智能体，第 35 章）完成；大仓库可先用探索型子智能体产出结构摘要再带读。
- 锚点来自目标仓库真实源码（工作区文件系统，第 27 章），非 DSH 本体。
- 正文用中性能力描述，落地映射到 DSH 实际工具名（见 DESIGN.md 第 1 档）。

## 反模式
- 上来逐个文件翻译，没有骨架和主线。
- 编造行号 / 没验证的调用关系。
- 讲完不给阅读顺序，用户无从继续。

## 验证
五段齐全；主线是一条真实可跳转的端到端链路；每个关键锚点来自实际读取过的代码。

## 脚本与样例（scripts/ · examples/）
- `scripts/scan.mjs` — 陌生仓库的**机械骨架扫描**，产出带读起点清单(markdown)。**零第三方依赖，仅需 Node ≥18**。
  - 用法：`node scripts/scan.mjs [dir] [--out report.md] [--depth N] [--top N]`
  - 输出：① 扩展名分布（文件数·行数）② 疑似入口启发式（main/cli/app/server/__main__/package.json 的 main·bin 等，**先读这些建主线**）③ 核心大文件 Top N（按行数）④ README 摘要。
  - 定位：它是「鸟瞰起点」，不做语义判断；模型据此挑入口，再用 grep/read 沿调用链建立真实生命周期主线与 `文件:行号` 锚点。
- `examples/scan-sample.md` — 对本移植包目录跑出的真实样例，展示五类输出长什么样。
- **DSH 落地**：带读任何仓库（含 DSH 本体）时，先 `node scripts/scan.mjs <repo> --out skeleton.md`，把结果作为「整体骨架」段的输入，再逐段展开。无 Node 时退化为用 DSH 文件工具手工统计。
