# 交付反馈模式档案 —— 一份决策胶片从 v1 改到 v5 学到的东西

> `SKILL.md` §五 是精炼版规则,本文是**为什么**——来源于一次完整的决策胶片共创(11 页、8 轮反馈、5 个版本)。规则拿不准时回查这里的模式与判据。
>
> 本文只保留可迁移的方法论,不含具体项目、素材与人称信息。

## 一、内容与措辞

| 规则 | 为什么 / 判据 |
|---|---|
| 量化一律正值表提升,原口径小字括注 | 同页一会儿正值一会儿负值,读者要在脑子里换算方向,结论就糊了。统一成「提升」方向(耗时 -91.2% → 11.4×;-41% → +69%;-29.2% → +40%),换算必须数学等价,原口径保留在括注里防追问 |
| 全篇量化数字统一主强调色 | 「这一页的数字是蓝的,那一页是黑的」——数字是全篇最需要被扫到的一类信息,颜色必须一致。改的时候要**全篇查一遍**:hero 数字、stat 块、树状统计、量化条;分类标签(A/B 线)与状态色(证伪 / 警示)不算数字,各归各色 |
| 生硬词替换 | 契约→规范;深潜→深入;呼应→结语;锁到→锁定到;抬到 / 上抬→迁移到 / 升级到(拗口,连续两轮被点名);变贱→变廉价;不信散文→不认自然语言描述;守正确→把关正确性 |
| 归属精确 | 同一个人在不同社区的产出要分清:文章归文章的社区,代码 / skill 归项目的社区;提到合入要写**具体仓库名**,不说「合入上游」 |
| 事实时效 | 「注脚已经滞后了,现在 PR 都整改合入了」——凡是引用 PR / 特性状态,上片前拉一次 API 取 state / merged_at / 描述要点,别沿用旧稿 |
| 业务数字以用户口述为准 | 篇数、浏览量、期数这类业务数字,用户给什么用什么,不去「考证修正」;存疑就问,别自己改 |
| 引文定稿要锁死 | 结尾金句这类会被反复引用的句子,一旦定稿就不再润色,原文与译文一并锁定 |

## 二、忠实呈现(返工最狠的一类)

- **用户给定的标题一字不差**:用户亲手写的标题、或明确要求「从我历史记录里找真实标题」的,必须是真实原文,不许自拟近似的。自拟一次就要全部推翻重来。
- **引用一段指令,就要看起来像指令**:把用户的自然语言指令改写成 `while` / `for` 伪代码,是典型的过度加工——原貌是这条内容的价值所在。正确做法:保留原语气做文字精简 + 缩进层级 + 行尾 `↔` 小注做对应关系。
- **参照物先打开**:用户会精确指到「某胶片第 7 页左边」「某知识卡」「大纲第 45 行」「某次会话」——这些都真实存在,先渲染 / 读原文再动手。找不到就问,**禁猜**:凭空造一页出来,得到的反馈是「要么有效补充,要么找我要材料」。

## 三、版式细节

- **同列左对齐**:同一栏里的引句与下方 bullets 用了不同的 x,被连续三轮点名。修法是同一个 midX 变量统一驱动;修完放大渲染图逐像素验证。
- **图大于文**:反复出现的要求是「图片拉大一点 / 铺满 / 不要变形」——文字压紧上移给图让位;三联图比例一致;顶部背景卡要矮 + 文字垂直居中。
- **裁剪要谨慎**:为统一比例裁了截图,下一轮可能被要求「还是用原始的吧」。裁剪属于可逆试探,渲出来给用户选,别当定稿。
- **留白失衡 = 不合格**:「太空了」「排版散」是高频反馈。每页渲完自问密度;空就补真实素材,或开口要材料。
- **箭头正交**:流程分叉用斜线会被判「错乱」——竖干 + 水平箭头。
- **mini 装饰图**与卡框留 ≥0.12" 间距;**hero 数字居中**。

## 四、形象素材(三轮迭代的教训)

1. 第一轮:自己画了个抽象图形当形象 → 否,「要那个具体形象」。
2. 第二轮:自己原生画了个近似的小动物 → 否,「有点丑,直接拿官方的图标」。
3. 定稿:用**官方素材**(从官方演示资源里抽帧裁剪),按用户自己的主题配色重着色,再按逻辑像素网格重建以保住直边与左右对称。
4. 用途分层:**大形象**用于封面 / 论点页 / 末页,**小标签**用官方标识重着色(深底用浅色版、浅底用主色版)。
5. **方法论**:涉及某产品品牌形象时,先查用户已有的主题配置文件与官方素材源——「我之前调过颜色」这类话是最强的定位线索。自绘替代物几乎必被否。素材授权自行核实。

## 五、工程陷阱(已踩过)

- pptxgenjs `sizing: {type: "contain"}` 经 LibreOffice 渲染会**拉伸变形** → 手工等比:实测宽高比进 ASPECT 表,自算 w/h 居中。
- 富文本多 run 各自带 fontSize 时,几何审计用外层字号估宽会误报——顶层补一个近似 fontSize。
- JPEG 抽帧抠图有 1–2px 锯齿 → 逻辑像素网格投票重建;PIL bbox 裁剪受 JPEG 底噪干扰,改用阈值化或固定裁。
- LibreOffice 渲 emoji(🚫 等)可能字形错乱——状态符收敛到 ✅ ❌ ➖ ⚠️。
- 大字号文本含全角逗号时估宽会变,大标题改字后必须复核换行。

## 六、协作节奏

- 每轮反馈**逐条对账**回复(表格:反馈 → 落地),用户会核对每一条。
- **不要「没改假装改了」**:±0.1" 的微调用户看不见,就等于没改——要改就改出肉眼可见的差异,渲染前后自比。
- 大改(加页 / 换主题 / 换结构)新起 `build_deck_vN.js` 留基线;小改就地改;产物 pptx 文件名跟版本走。
- 每一版的闭环:几何审计过 → 渲染逐页目检 →(大改时)`humanize-check` 独立门禁 → 拼总览图 → 交付 → 按目标仓库约定提交(仅本任务文件、英文 commit message)。
