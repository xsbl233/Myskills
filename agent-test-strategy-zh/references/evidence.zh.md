# 证据：智能体自写的测试

来源：Chen, Sun, Shi, Peng, Gu, Lo, Jiang. *Rethinking the Value of Agent-Generated Tests
for LLM-Based Software Engineering Agents.* arXiv:2602.07900v2（初版 2026-02-08，修订 2026-04-09）。

## 实验设置

- 基准：SWE-bench Verified（500 个实例，12 个 Python 仓库）。
- 脚手架：mini-SWE-agent —— 只有 bash 工具，没有专门的测试工具，也没有强制的测试阶段。
  唯一的测试提示是默认 prompt 里一句建议性的话。
- 模型：六个代表性模型家族，各取排名最高的那一版。

## 写测试的频率（论文表 1）

| 模型 | 解决率 | 写了测试的任务占比 | 平均测试数* |
|---|---|---|---|
| Claude Opus 4.5 | 74.4% | 83.0% | 3.52 |
| Gemini 3 Pro | 74.2% | 61.6% | 2.05 |
| GPT-5.2 | 71.8% | 0.6% | 1.00 |
| Kimi K2 Thinking | 63.4% | 97.4% | 3.61 |
| MiniMax M2 | 61.0% | 98.6% | 5.19 |
| DeepSeek v3.2 Reasoner | 60.0% | 89.2% | 3.75 |

\* 仅统计至少写了一个测试产物的任务。

同一模型内部，已解决与未解决任务的写测试比例相近；未解决任务有时写得更多，
作者把它解读为难题触发了更多试错。

## 测试里到底有什么

打印中间值的 print 始终多于基于断言的检查。断言以局部性质检查和精确值比较为主。
换句话说，这些测试主要充当补丁开发过程中的观测通道。

## 提示干预（四个模型）

鼓励或压制新建测试文件，对解决率影响很小，对成本影响明显：

- 诱导写测试：token 与交互轮次上升，成功率没有提升；
- 压制写测试：成本大幅下降，成功率小幅下降。

论文的总结句是：当前智能体自写的测试"更多改变了过程与成本，而不是最终任务结果"。
它把写测试描述为一种依赖模型的过程风格，而不是能力驱动因素。

## 推广前要知道的边界

- 单一基准、Python 仓库、单一轻量 bash 脚手架。强制测试的脚手架（例如把测试先行拆成
  多个子 agent 的工作流）是另一种机制，表现可能不同。
- 研究对象只是**智能体自写**的测试。人写测试或隐藏测试作为外部判据，不是同一种处理，
  且普遍报告为有正向作用。
- 结论是均值与显著性层面的，不是说测试对某个具体任务从无帮助。论文本身也探讨了
  哪些 issue 类型可能受益。

## skill 如何取用这些结论

- 默认用用完即弃的探针代替落库测试：探针保留了论文测到的观测价值，又不必为论文认为
  低产的测试资产付费。
- 真正的判据留在外部：已有测试套件、用户复现、隐藏测试。
- 把写测试当成预算决策，而不是习惯。
